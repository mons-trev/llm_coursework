T08 Error analysis — GPT-4o mini
분석 범위: 시스템 프롬프트 한글화 전 저장 기록. 추가 API 호출 없이 중간 계획을 metric.py로 재평가함.

1. 사용자 요청
평소 외식을 자주 해서 나트륨 섭취량을 줄이려고 해. 이틀 동안 점심과 저녁을 추천해 줘. 하루에 먹는 두 끼의 나트륨 합계는 1,600mg 이하여야 하고, 각 끼니는 350~750kcal여야 해. 전체 45,000원 이하, 한 끼 15,000원 이하로 해줘.

2. 관찰된 실행
세 라운드 모두 Planner 호출 한도(각 6회)에 도달했다.
search_foods 9회, compute_plan 9회. 고유 계획은 2개이며 두 번째 계획을 8회 계산했다.
Verifier 도구 호출은 0회다. 최종 상태는 not_verified, 최종 plan은 null이다.

3. 반복된 두 번째 계획의 위반
1일차 점심: 콩나물국밥 + 잡채밥 → 18,000원, 990kcal (한 끼 15,000원 및 750kcal 상한 초과)
2일차 점심: 제육볶음 + 콩국수 → 21,000원, 1,070kcal (동일한 상한 초과)
총비용: 52,400원 > 45,000원
1일차 나트륨: 1,608.6mg > 1,600mg
2일차 나트륨: 2,677.98mg > 1,600mg
각 음식이 검색 조건을 만족해도 같은 끼니나 하루로 합쳤을 때의 조건은 만족하지 못했다.
첫 계획에서 저녁 메뉴를 바꿨으나 위반된 점심 조합은 그대로 남았고 이후 동일 계획을 반복했다.

4. metric.py 리포트 해석
공식 리포트의 실패 항목은 slots_complete다. 최종 식단이 없어 요청한 네 끼가 모두 누락됐기 때문이다.
다른 수치 항목의 passed=true는 식단이 없어서 검사 대상이 비어 나온 값이며, 실제 조건 충족을 뜻하지 않는다.
위의 중간 계획 위반은 원래 실행에서 Verifier가 검출한 것이 아니라 이번 사후 분석에서 metric.py로 확인한 것이다.

5. GPT-5 mini 비교
동일 요청을 1라운드에 통과. 총비용 38,000원, 하루 나트륨 894.0mg / 1,443.4mg.
따라서 이 데이터에서 조건을 충족하는 계획이 존재함은 확인된다. 단일 실행 결과로 모델 전반의 능력을 일반화하지 않는다.

6. 발표용 요약
GPT-4o mini는 개별 음식 검색에는 성공했으나, 여러 음식을 조합한 끼니 및 하루 단위의 제약을 동시에 충족하도록 계획을 수정하지 못했다. 위반한 동일 계획을 반복 계산하면서 호출 한도에 도달했고, Verifier에 전달할 최종 계획을 반환하지 못했다. 이는 복합 제약 수정 실패와 Planner–Verifier 전달 단계의 한계를 보여 준다.

7. 개선 가설 (구현·추가 API 실험은 수행하지 않음)
- 동일 계획 반복을 감지하면 계산된 임시 후보를 Verifier로 전달한다.
- 끼니별 초과 가격·열량과 하루별 초과 나트륨을 수치로 명시한 피드백을 제공한다.
- 단순 호출 한도 증가와 조기 검수를 같은 예산 안에서 비교한다.
- 최종 식단 누락과 수치 조건 위반을 분리해 집계한다. 원래 평가 파일과 점수는 변경하지 않는다.
