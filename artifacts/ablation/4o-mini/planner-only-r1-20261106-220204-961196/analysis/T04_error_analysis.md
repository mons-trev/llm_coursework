# T04 검색 어휘 오류와 빈 식단 제출

GPT-4o mini Planner-only 1회 실험에서 T04는 음식 분류 검색에 `한식` 대신 `Korean`을 사용해 검색 결과를 얻지 못했다. 이후 빈 식단을 반복 제출해 공통 JSON 스키마 검사를 통과하지 못하고 종료됐다.

실행 기록은 `artifacts/ablation/4o-mini/planner-only-r1-20261106-220204-961196`에 저장되어 있다. 아래 사후 확인은 저장 기록과 로컬 DB를 사용한 분석이며, 실행 중 Planner에 전달한 피드백이나 추가 모델 실행 결과가 아니다.

## 사용자 요청과 실행 결과

> 근력운동 중인 대학원생이야. 이틀 동안 점심과 저녁을 한식으로만 추천해 줘. 각 끼니마다 단백질은 최소 30g, 열량은 350~750kcal여야 해. 4끼 총예산은 45,000원 이하, 한 끼에 11,000원 이하로 해줘.

| 항목 | 기록 |
|---|---|
| 모델과 모드 | `gpt-4o-mini`, `planner_only` |
| 반환 상태 | `not_verified` |
| 종료 원인 | `technical_execution_failure` |
| 모델 호출 수 | 7회 |
| 도구 실행 수 | `search_foods` 4회, `compute_plan` 0회 |

| 실제 반환 식단 | 없음 |
| 턴 소요 시간 | 약 15.73초 |

## 실제 실패 과정

첫 라운드에서 Planner는 아래 인자로 `search_foods`를 4번 호출했다. 모든 호출의 검색 결과는 빈 리스트 `[]`였다.

```json
{
  "cuisine_types": ["Korean"],
  "kcal_min": 350,
  "kcal_max": 750,
  "protein_min": 30,
  "price_max": 11000
}
```

위 예시는 사용한 필터만 발췌한 것이다. 나머지 검색 필터는 `null`이었다. DB의 음식 분류 값은 한국어 `한식`이므로 `Korean`과 일치하지 않았다.

Planner는 검색 인자를 수정하지 않고 다음 최종 응답을 제출했다.

```json
{"plan": {}}
```

공통 스키마 검사는 비어 있는 식단을 허용하지 않아 `root: {} should be non-empty` 오류를 냈다. Planner에게는 전체 식단을 포함한 JSON 객체를 반환하라는 기술적 피드백이 전달됐다. 이 피드백에는 검색 분류를 `한식`으로 바꾸라는 구체적인 진단이 없었다.

두 번째와 세 번째 라운드에서도 Planner는 추가 검색이나 계산 없이 동일한 빈 식단을 제출했다. 3개 라운드를 소진한 뒤 식단을 반환하지 못했다. 기록의 `not_verified`는 기존 실패 상태 이름이며, 이 실행에서는 Verifier가 실행되지 않았다.

## 사후 확인한 검색 인자와 실행 가능성

첫 검색의 다른 인자를 유지하고 `cuisine_types`만 `["한식"]`으로 바꾸자 다음 4개 음식이 검색됐다. 수치는 DB의 1인분 기준이다.

| 음식 코드 | 음식 | 가격 | 열량 | 단백질 |
|---|---|---:|---:|---:|
| F048 | 된장찌개 | 8,500원 | 550kcal | 38.55g |
| F020 | 제육볶음 | 10,000원 | 370kcal | 38.5g |
| F032 | 순대국 | 10,000원 | 544kcal | 43.52g |
| F010 | 콩국수 | 11,000원 | 700kcal | 32.27g |

위 음식을 각각 한 끼에 배치하면 총 39,500원이며, `metric.evaluate_plan`으로 사후 확인한 모든 조건을 통과한다. 이 조합은 분석 시 구성한 예시이고 실제 모델의 반환 식단은 아니다.

## 원인과 평가 해석

관찰된 원인은 **도구 인자의 DB 어휘 불일치와 해당 오류의 자체 수정 실패**다. 검색 결과가 비자 Planner가 빈 식단을 제출했고, 기술적 재시도에서도 검색 인자를 고치지 못했다. 독립 평가에서는 요구된 4개 슬롯이 모두 누락되어 `slots_complete`가 실패했다.

이 사례는 최종 식단 미반환으로 집계한다. 빈 식단에서 일부 영양·가격 검사가 통과하는 것은 조건을 충족한 식단 생성 성공을 의미하지 않는다. 또한 이번 한 번의 실행만으로 Planner + Verifier와의 성능 차이를 주장할 수 없다.
